## 一、Stage 4 留下的小事（建議優先收尾）

### 1.1 iOS Google Maps app scheme 沒裝 app 的 fallback chain

> 狀態更新（2026-07-20）：已實作（commit `3d88284`），待真機驗證（T6 checklist 第 5 節）。

**問題**
iOS 上 ExternalNavSheet 點 Google Maps 選項，若使用者沒裝 Google Maps app，`comgooglemaps://` URL 會在 Safari 內**靜默失敗**：沒跳錯誤、沒 fallback、什麼都沒發生，使用者會困惑。

**目前實作**
`src/components/map/ExternalNavSheet.tsx` 的 `handlePick`：`window.location.href = url` 直接跳，不偵測是否成功。

**預期行為**
按下 Google Maps（iOS app scheme）選項：
1. 記錄當下時間 t0
2. `window.location.href = appSchemeUrl`
3. setTimeout 2500ms 後檢查：如果頁面還在 visible（`document.visibilityState === "visible"`）且時間差距小，假設 app scheme 失敗，fallback 到 web URL（`https://www.google.com/maps/dir/?...`）

**影響檔案**
- `src/lib/mapbox/deep-link.ts`（加 helper `tryAppSchemeWithFallback` 或產生 fallback URL pair）
- `src/components/map/ExternalNavSheet.tsx`（`handlePick` 改用 helper）

**預估**：1h

### 1.2 RouteSheet「+ 從收藏選」在 ≥5 點時的呈現

**問題**
`MAX_WAYPOINTS = 5`，目前 `src/components/map/RouteSheet.tsx` 用 `selectedSpots.length < MAX_WAYPOINTS` 判斷按鈕顯示。到上限時按鈕**整顆消失**，使用者可能困惑「咦剛剛還在的按鈕呢」。

### 1.3 Saved picker 空狀態文案優化

**問題**
使用者收藏的景點若不在當前 `/api/spots` viewport 內，picker 顯示「本區無已收藏景點」。使用者可能不知道**為什麼**沒有，因為他剛剛明明收藏過。

**目前文案**
`src/components/map/RouteSheet.tsx`：

```
savedIds.length === 0  → "尚未收藏景點 · 試試在景點頁面按收藏"
有收藏但本區 0          → "本區無已收藏景點 · 試試拖動地圖或擴大搜尋範圍"
```

**影響檔案**
- `src/components/map/RouteSheet.tsx`

**預估**：15min

### 1.4 LocateMeButton 跟 sheet 的動畫曲線不協調

**問題**
- RouteSheet 用 framer-motion spring（`stiffness 320, damping 34`）滑入滑出
- LocateMeButton 用 CSS transition `bottom 0.3s ease-out` 跟著移動
- 兩個 timing 不對齊，sheet 進場時按鈕慢半拍

**預期行為**
LocateMeButton 也用 framer-motion 跟著 spring 移動（或調 CSS bezier 接近 spring 曲線）

**選項**
- A. 把 LocateMeButton 改成 motion.button（小重構，最自然）
- B. CSS transition 用 `cubic-bezier(0.32, 0.72, 0, 1)` 模擬 spring（最小改動）

**影響檔案**
- `src/components/map/LocateMeButton.tsx`

**預估**：20-30min（試幾個曲線）

### 1.5 RoutePolyline 主題切換時的顏色更新

**問題（待驗證才知道要不要修）**
`src/components/map/RoutePolyline.tsx` 用 `getComputedStyle` 讀 `--accent` 包在 `useMemo([theme])`。理論上 theme 變動 → useMemo 重算 → React 重 render `<Layer>` → Mapbox 重套色。

但 Mapbox style 變動本身有處理時間，theme 切換的瞬間可能有 1-2 frame 顏色不對。

**驗證方式**
跑 dev，快速切 theme（terminal/blueprint/caution/midnight），肉眼看路線顏色有沒有跳變或殘留。

**如果有問題**
改用命令式 API 直接更新 paint，避開 Source/Layer 重 mount：
```typescript
mapRef.current?.getMap().setPaintProperty('oddspot-route-line', 'line-color', accent);
```

**影響檔案**
- `src/components/map/RoutePolyline.tsx`
- 可能要 `src/components/map/MapView.tsx` 傳 mapRef 進來

**預估**：30min（先驗證再決定要不要修）

### 2.2 雷達 / leader-line 進場視覺（已預埋 TODO）

**目標**
第一次進地圖時，從使用者位置朝附近每個 spot marker 畫出 1px 虛線
+ 旋轉雷達掃描環（acid/Y2K 雷達 UI 風格）。

**詳細規格**
見 [.ai-context/features/map/_module.md](../../.ai-context/features/map/_module.md) 「未排程 / Stage 5+ polish 候選」段落。

**觸發時機**
- 地圖首次載入完成（mapbox `'load'` event）
- 有 userLocation
- 至少 1 個 spot 可見
- localStorage 沒有 `oddspot-radar-seen` flag

**不觸發**
- 路線規劃中（route !== null 或 selectedSpots.length > 0）
- 使用者拖動過地圖後
- 已 seen 過

**實作思路**
- 新增 `<RadarLeaderLines />` 元件，掛在 `<Map>` 內
- 用 `<Source>` 加 N 條 GeoJSON LineString（user → spot）為 dashed line
- 用 SVG overlay 畫旋轉雷達環（不是 mapbox layer）
- 進場後 ~3s 自動 fade out
- 完成後 `localStorage.setItem("oddspot-radar-seen", "1")`

**影響檔案**
- 新增 `src/components/map/RadarLeaderLines.tsx`
- 改 `src/components/map/MapView.tsx`（mount）

**預估**：3-4h

## 六、操作流程提醒（給下個 session 看的）

下個 session 開啟後請：

1. **先讀完所有必讀文件**（CLAUDE.md / .ai-context 系列 / 本文件 / 上一階段 spec）
2. **不要直接動手**，先把選定的範圍跟使用者對齊
3. 給使用者 commit 拆解計畫，等確認後才寫 code
4. 每顆 commit 前說明範圍，等確認後才 commit
5. 每顆 commit 後跑 `npm run build` 驗證
6. 全部完成後告訴使用者，等他跑 dev 視覺驗證
7. 視覺 OK 後等使用者說再 push（不要主動 push）

**約束（沿用 Stage 4）**：

- 不可執行 `npm run dev`（port 8083 限制）
- 任何 git 操作前必須先說明意圖、等使用者明確確認
- 高風險操作（force push / reset --hard / branch -D）即使同意也要再次確認
- 最小影響範圍，不順便重構別處
- TypeScript 完整型別，不用 `any`
- 中文簡潔註解，不過度 emoji
- 每次 commit 前跑 `npm run build` 驗證零 error

**新 worktree 啟動 checklist**：

- 從 `main` 開新 worktree（確保拿到 Stage 4 已 merge 的版本）
- 把主 repo 的 `.env.local` 拷到新 worktree（NEXT_PUBLIC_MAPBOX_TOKEN 等）
- 跑 `npm install`
- 跑 `npm run build` 確認基線通過
